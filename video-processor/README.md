# video-processor

Локальная команда `vidoc URL` скачивает полное YouTube-видео и распознаёт речь на Mac. Распознавание выполняет multilingual-модель faster-whisper `small` на CPU с INT8. Это исходная расшифровка с временными отметками; редакторская обработка в `vidoc URL` пока не реализована. Отдельный инструмент локальных экспериментов описан ниже.

## Установка

Нужны Python 3.11+ и системные `ffmpeg` и JavaScript runtime. Для YouTube установлен пакет `yt-dlp[default]` с компонентом решения JS challenges; runtime устанавливается отдельно. Поддерживаются Deno и Node, доступные через `PATH`.

Из корня репозитория:

```bash
brew install ffmpeg deno
cd video-processor
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[dev]'
vidoc --help
vidoc 'https://www.youtube.com/watch?v=OdpcOLrxBnA'
```

Если установлен только Python 3.11 или новее под другим именем, используйте его вместо `python3.12`.

Первый запуск скачивает веса модели из Hugging Face в корневую `artifacts/.models/`. Для скачивания видео, метаданных и первых весов нужен интернет. Последующее распознавание выполняется локально; повторный запуск всё равно обращается к YouTube за метаданными.

## Результат

Независимо от текущего каталога команда сохраняет файлы в корень репозитория:

```text
artifacts/<безопасное название>-<YouTube ID>/
  video.mkv          # либо исходный контейнер, если объединение не потребовалось
  transcript.txt
  source.json
```

Строки `transcript.txt` имеют вид `[00:01:05 → 00:01:10] Распознанная речь`. `source.json` содержит исходный URL, YouTube ID, название, определённый моделью язык и имя модели. Каталог и имя файла видео могут содержать кириллицу; опасные символы в названии заменяются, длина ограничивается.

Повторный запуск использует тот же каталог и завершённый видеофайл. Старые `transcript.txt` и `source.json` удаляются перед обработкой; новые публикуются после успешного распознавания. При ошибке после определения каталога новые TXT/JSON отсутствуют, временный WAV удаляется, видео остаётся. Если ошибка произошла раньше, например при запросе метаданных, результаты предыдущего запуска могут оставаться; код завершения и сообщение CLI показывают неуспех текущей попытки. Части незавершённого скачивания остаются в `.download/` для продолжения yt-dlp. Ошибка сопровождается названием этапа и кодом 1, Ctrl-C — кодом 130. Отсутствующий `ffmpeg` выявляется до обращения к сети.

Обрабатывается одно обычное видео; плейлисты, текущие и запланированные эфиры не поддерживаются. Параметр `list` в ссылке watch не включает скачивание плейлиста. Запускайте одну обработку конкретного видео за раз: блокировки параллельных запусков в MVP нет. Продолжительность и качество распознавания зависят от CPU, языка и аудио; модель может ошибаться, проверяйте важные фрагменты по видео. Установленная копия вне исходного репозитория не поддерживается.

Артефакты, веса, кеши и `.venv/` исключены из Git.

## Устройство процессора

`pipeline.py` определяет последовательность обработки, допустимость видео, имена результатов и файловый жизненный цикл: временное аудио, публикацию TXT/JSON и очистку при ошибке или отмене. Зависимости передаются явно через контракты `VideoDownloader`, `AudioExtractor` и `SpeechRecognizer` из `ports.py`. Метаданные видео, сегменты и результат распознавания представлены собственными типами `VideoInfo`, `Segment` и `Transcription`; результат сообщает имя использованной модели для `source.json`.

Адаптеры `adapters/ytdlp.py`, `adapters/ffmpeg.py` и `adapters/whisper.py` содержат обращения к инструментам и преобразуют их данные в типы процессора. CLI непосредственно создаёт адаптеры и задаёт общий корень артефактов, кеша yt-dlp и весов модели. Сценарий не импортирует адаптеры; адаптеры не вызывают соседние этапы и не выводят сообщения в терминал. Тяжёлые библиотеки загружаются при вызове адаптера, поэтому `--help` не загружает движок распознавания.

Правило добавления и замены этапов закреплено в [ADR 0005](../docs/adr/0005-processor-ports.md).

## Локальный эксперимент с редактурой

Из корня репозитория, с активным окружением сервиса:

```bash
python video-processor/scripts/edit_transcript.py \
  --transcript 'artifacts/<видео>/transcript.txt' \
  --output-dir 'artifacts/<видео>/editing' \
  --facts 'artifacts/<видео>/facts.json' \
  --title 'Название видео' \
  --prepare-only
```

`--transcript` и `--output-dir` обязательны. Относительные пути считаются от текущего каталога; инструмент не привязан к конкретному видео. Вход TXT использует формат временных отметок основной команды. Необязательный JSON `--facts` содержит массив `claims` с `timestamp` (секунды или временная отметка/интервал); записи могут включать `id`, `claim_ru`, `status`, `finding_ru`, `editor_action_ru`, `allowed_normalization`. Необязательный массив `canonical_names` задаёт написание имён; без него словарь собирается из `allowed_normalization`. Без `--facts` оба списка пусты. Заголовок по умолчанию — «Отредактированная расшифровка».

`--prepare-only` сохраняет `manifest.json` и `requests/*.json`, не обращаясь к модели. Для полного прогона уберите этот флаг: требуется запущенная Ollama на `http://127.0.0.1:11434` с установленной `qwen3.5:9b-q4_K_M`. Инструмент сохраняет сырые ответы в `raw/`, проверенные ответы в `responses/`, блоки в `output-blocks.json`, состояние в `progress.json` и текст в `article.md`. Возобновление использует проверенный завершённый ответ только при совпадении хеша запроса. Структурная проверка ответа не доказывает верность содержания источнику; качество результата требует отдельной проверки по ADR 0004.

Выбирайте отдельный каталог результатов для каждого прогона: выходы с одинаковыми именами обновляются. Перезапись входного TXT или справки любым выходным файлом запрещена до начала записи. Одновременные запуски в одном каталоге не поддерживаются. Код и промпт находятся в Git, данные запросов и результаты — в `artifacts/`.

## Проверки

В каталоге `video-processor` с активным окружением:

```bash
pytest
ruff check .
vidoc --help
```

Тесты проверяют реальные файловые операции, безопасные пути, единичную обработку, временные отметки, ошибки этапов и очистку. YouTube, ffmpeg и модель подменяются на внешних границах; успешные unit-тесты не доказывают реальную транскрипцию.
