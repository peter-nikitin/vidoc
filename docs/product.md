# Продуктовые задачи Vidoc

Статус: согласованное направление продукта, 2026-10-04. Этот документ описывает результат для пользователя, а не интерфейс или техническую архитектуру.

## Проблема

У пользователя есть много длинных подкастов, лекций и выступлений, которые он хочет изучить. Просмотр занимает слишком много времени, а ускоренное прослушивание неудобно. Обычная автоматическая расшифровка тоже плохо подходит для чтения из-за особенностей устной речи.

## Главная задача

Когда пользователь находит длинное YouTube-видео, которое хочет изучить, он даёт Vidoc ссылку и получает текст, который удобно прочитать вместо просмотра, сохранив содержание и ход мысли автора.

## Первый этап: один верный источнику текст

Для одного YouTube-видео Vidoc:

1. Получает речь из исходного видео.
2. Превращает распознанную речь в связный текст: убирает речевой мусор и механические повторы, восстанавливает пунктуацию, предложения и смысловые абзацы.
3. Сохраняет существенные мысли, аргументы, порядок рассуждения и значимые оговорки автора.
4. Не выдаёт догадки или дополнительные факты за слова автора. Неясные места обозначает как неясные.
5. Сохраняет возможность сверить спорный фрагмент с исходным видео. Конкретная форма этой связи будет определена позже.

Результат этапа — **один читаемый текст одного видео**. Он не обязан быть дословным, но должен оставаться верным источнику. Качество оценивается одновременно по удобству чтения и по точности при сверке с видео. До выбора технического решения нужно определить набор примеров и процедуру такой оценки.

## Следующие продуктовые задачи

- **Управлять сокращением:** после получения стабильного верного источнику результата пользователь сможет выбирать, насколько сильно сокращать материал.
- **Видеть визуальный материал:** пользователь сможет читать текст вместе с важными кадрами видео, в частности со слайдами лекций и конференций.
- **Разбирать сложные места:** пользователь сможет попросить раскрыть мысль или привести пример на знакомом ему языке программирования. Созданное системой объяснение должно быть ясно отделено от содержания источника.

Эти задачи фиксируют направление продукта и не входят в первый этап.

## Исследовательская цель

Проект также служит практикой работы с локальными и удалёнными языковыми моделями. Выбор модели, провайдера и способа обработки следует делать по результатам проверки качества и эксплуатационных ограничений, а не закреплять в продуктовом описании заранее.
